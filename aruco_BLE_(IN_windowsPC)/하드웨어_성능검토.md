# ArUco 추적 장치 성능 비교

대회용 위치·방향 측정은 Windows 노트북을 사용한다. 2026-09-10 동일 4K 이미지 검출 시험에서 노트북의 처리량은 Pi 5의 약 2.46배였다.

## 검출 연산 측정

| 항목 | Windows 노트북 | Raspberry Pi 5 |
|---|---:|---:|
| 장치 | ASUS Zenbook Duo UX8406CA | Pi 5 Model B Rev 1.1, 4GB |
| 프로세서 | Core Ultra 9 285H, 16코어 | Pi 5 내장 프로세서 |
| OpenCV / 검출 스레드 | 5.0.0 / 4개 | 5.0.0 / 4개 |
| 측정 반복 | 180프레임 | 180프레임 |
| 반복 루프 처리량 | **20.69fps** | **8.42fps** |
| 회색 변환+검출 평균 | 47.80ms | 118.76ms |
| 회색 변환+검출 중앙값 | 42.94ms | 116.73ms |
| 회색 변환+검출 p95 | 69.72ms | 134.35ms |
| 회색 변환+검출 최댓값 | 89.69ms | 141.17ms |
| 전체 마커 검출 횟수 | 2,820 | 2,820 |


3840×2160 ChArUco 이미지 6장을 메모리에 올려 각각 30회 처리했다. 두 장치에서 OpenCV 5.0.0, 검출 스레드 4개, `track_aruco_4k.make_detector()`와 `DICT_4X4_50`을 사용했다. 측정 구간은 **메모리의 BGR 이미지 → 회색 변환 → 마커 검출**이다. p95는 이 검출 연산 처리 시간의 95%가 해당 값 이하임을 나타낸다. 카메라 입력·위치와 방향 계산·필터·BLE 전달까지 포함한 전체 추적 FPS와 촬영부터 차량 수신까지의 지연은 아래 경기장 시험에서 평가한다.

Pi는 공식 쿨러를 사용하고 VS Code 등 기존 작업을 유지한 상태에서 `nice 10`으로 실행했다. 온도는 47.95→52.35°C, 실행 전후 `get_throttled`는 `0x0`이었다. 입력 BGR 6장은 약 142.4MiB를 사용했다. 평균 118.76ms 중 검출이 114.54ms로 약 96.4%를 차지해, 검출 연산을 우선 최적화 대상으로 잡았다.

## 노트북 Bluetooth 구성

| 항목 | 확인된 값 |
|---|---|
| Bluetooth 장치 | Intel Wireless Bluetooth |
| USB ID | `VID_8087&PID_0037` |
| 드라이버 | `24.20.0.3` |
| Wi-Fi 장치 | Intel Wi-Fi 7 BE201 320MHz |

Windows 기본 Bluetooth 스택은 라디오 한 개를 지원하며, 동시 BLE 연결 수와 연결 중 스캔 가능 여부는 어댑터 하드웨어에 의존한다. 차량 5대의 동시 연결·전달 성능은 아래 경기장 시험에서 차량별 수신률과 지연으로 평가한다. [Bleak 연결 설정](https://bleak.readthedocs.io/en/latest/api/client.html), [Microsoft Bluetooth 구성](https://learn.microsoft.com/en-us/windows-hardware/drivers/bluetooth/bluetooth-faq)

## 경기장 측정 항목

1. 여러 위치·방향에서 차량 마커를 가렸다가 정지 상태로 다시 노출하고, 첫 유효 검출 시간과 위치·방향 오차를 기록한다.
2. 기존 Wi-Fi 작업과 함께 Pi 5대에 2분간 좌표를 보내고, 차량별 수신 수·누락·측정값 나이·p95/최대 지연·전달 기한 초과 횟수를 기록한다.
3. 한 차량의 BLE 서비스를 중단·복구하는 시험을 3회 반복하고, 나머지 차량의 수신 지속과 복구 차량의 최신 좌표 수신을 기록한다.
